# Agent质量研究：可核验经历与口播（2026-10-30）

可讲的成果是证据链诊断和受控验证。两处工程修复有确定性收益；总体答案质量仍没有得到充分证明。原始实验含私有语料，面试可展示代码、方法、聚合数据和已脱敏失败链。

简历可用表述：在AI协作下对群聊Agent建立候选召回、工具返回、模型可见和答案引用的分层诊断；基于冻结数据复用51次检索候选，修复容量和模型预算阶段的证据优先序丢失，在固定输入对照中恢复已知目标且无已知目标退化；通过真实Agent/Judge对照保留工程修复、拒绝未通过稳定性验证的Prompt候选。个人职责应按实际参与陈述，26份Review不是个人逐条人工审核，也不应声称全部实现由手工独立编写。

约一分钟口播：

“我遇到的不是检索完全没命中，而是命中后又被裁掉。系统先把语义chunk还原成消息，受100条容量限制；随后工具结果进模型还有一次预算裁剪，两个阶段都可能按时间把较新的高相关证据删掉。我沿用已有候选池做固定输入实验，只改保留优先序，展示仍按时间，预算和权限范围保持原合同。第一层让最高rank chunk整块丢失从19/51降到0，第二层在同一工具结果上把已知目标的模型可见次数从10恢复到14，没有发现已知目标丢失。真实A/B仍有归因和范围错误，所以我只把它说成可验证的工程修复。后来一句联合检索提示虽然改变了搜索行为，却出现预算失败，我没有因为某次答案更漂亮就采纳它。”

可追问的细节：

- 100条Capability与32k共享工具结果预算是两个边界；向量chunk不是最终引用来源，引用必须回到canonical消息。
- 字面命中优先、其余按语义排名保留；canonical展示顺序、Scope、Top-K和引用身份保持原合同。
- 不完整Reference之外不自动是假阳性；目标ID出现不证明自然语言事实采用；A/B分组还要核对候选路径是否实际触发。
- 剩591预算后的批次控制失败仍未解决；Provider未转义JSON失败保留，不靠重试或宽松解析隐藏。
